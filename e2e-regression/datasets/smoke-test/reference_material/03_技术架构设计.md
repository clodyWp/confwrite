# 技术架构设计

## 1. 系统架构

### 1.1 总体架构

系统采用微服务架构，基于 Spring Cloud 框架构建，主要分为以下几层：

```
┌─────────────────────────────────────────────────────────┐
│                    接入层 (Access Layer)                 │
│  Web 前端  │  移动端 APP  │  PDA 手持终端  │  第三方系统  │
└─────────────────────────────────────────────────────────┘
                            │
┌─────────────────────────────────────────────────────────┐
│                   API 网关层 (Gateway)                   │
│         Spring Cloud Gateway + JWT 认证 + 限流           │
└─────────────────────────────────────────────────────────┘
                            │
┌─────────────────────────────────────────────────────────┐
│                  业务服务层 (Service Layer)              │
│  入库服务  │  库存服务  │  出库服务  │  报表服务  │  基础数据服务  │
└─────────────────────────────────────────────────────────┘
                            │
┌─────────────────────────────────────────────────────────┐
│                   数据访问层 (Data Layer)                │
│      PostgreSQL  │  Redis  │  MinIO  │  RabbitMQ        │
└─────────────────────────────────────────────────────────┘
```

### 1.2 技术栈选型

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 前端 | Vue 3 + TypeScript | 3.4+ | 响应式 UI 框架 |
| UI 组件 | Element Plus | 2.5+ | 企业级组件库 |
| 后端 | Spring Boot | 3.2+ | 微服务框架 |
| 微服务 | Spring Cloud | 2023.0+ | 微服务治理 |
| 数据库 | PostgreSQL | 14+ | 关系型数据库 |
| 缓存 | Redis | 7.0+ | 内存缓存 |
| 消息队列 | RabbitMQ | 3.12+ | 异步消息 |
| 对象存储 | MinIO | 最新 | 文件存储 |
| 容器化 | Docker + K8s | 最新 | 容器编排 |

### 1.3 服务拆分

| 服务名 | 职责 | 端口 | 依赖 |
|--------|------|------|------|
| gateway-service | API 网关、路由、认证 | 8080 | - |
| inbound-service | 入库管理 | 8081 | base-service |

## 2. 数据库设计

### 2.1 核心表结构

**物料表 (material)**
```sql
CREATE TABLE material (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(50) UNIQUE NOT NULL,      -- 物料编码
    name VARCHAR(200) NOT NULL,            -- 物料名称
    spec VARCHAR(200),                     -- 规格型号
    unit VARCHAR(20) NOT NULL,             -- 单位
    category VARCHAR(50),                  -- 分类
    abc_class CHAR(1),                     -- ABC 分类 (A/B/C)
    safety_stock DECIMAL(18,2),            -- 安全库存
    min_stock DECIMAL(18,2),               -- 最低库存
    max_stock DECIMAL(18,2),               -- 最大库存
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

**仓库表 (warehouse)**
```sql
CREATE TABLE warehouse (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(50) UNIQUE NOT NULL,      -- 仓库编码
    name VARCHAR(200) NOT NULL,            -- 仓库名称
    address VARCHAR(500),                  -- 地址
    manager VARCHAR(100),                  -- 负责人
    status VARCHAR(20) DEFAULT 'ACTIVE',   -- 状态
    created_at TIMESTAMP DEFAULT NOW()
);
```

**库位表 (location)**
```sql
CREATE TABLE location (
    id BIGSERIAL PRIMARY KEY,
    warehouse_id BIGINT REFERENCES warehouse(id),
    code VARCHAR(50) UNIQUE NOT NULL,      -- 库位编码
    name VARCHAR(200),                     -- 库位名称
    zone VARCHAR(50),                      -- 区域
    capacity DECIMAL(18,2),                -- 容量
    status VARCHAR(20) DEFAULT 'AVAILABLE' -- 状态
);
```

**库存表 (inventory)**
```sql
CREATE TABLE inventory (
    id BIGSERIAL PRIMARY KEY,
    material_id BIGINT REFERENCES material(id),
    warehouse_id BIGINT REFERENCES warehouse(id),
    location_id BIGINT REFERENCES location(id),
    batch_no VARCHAR(100) NOT NULL,        -- 批次号
    quantity DECIMAL(18,2) NOT NULL,       -- 库存数量
    available_qty DECIMAL(18,2) NOT NULL,  -- 可用数量
    reserved_qty DECIMAL(18,2) DEFAULT 0,  -- 预留数量
    inbound_date DATE,                     -- 入库日期
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(material_id, warehouse_id, location_id, batch_no)
);
```

**入库单表 (inbound_order)**
```sql
CREATE TABLE inbound_order (
    id BIGSERIAL PRIMARY KEY,
    order_no VARCHAR(50) UNIQUE NOT NULL,  -- 入库单号
    supplier_id BIGINT,                    -- 供应商 ID
    supplier_name VARCHAR(200),            -- 供应商名称
    status VARCHAR(20) DEFAULT 'DRAFT',    -- 状态
    total_qty DECIMAL(18,2),               -- 总数量
    inbound_date DATE,                     -- 入库日期
    created_by VARCHAR(100),               -- 创建人
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

**入库单明细表 (inbound_order_item)**
```sql
CREATE TABLE inbound_order_item (
    id BIGSERIAL PRIMARY KEY,
    order_id BIGINT REFERENCES inbound_order(id),
    material_id BIGINT REFERENCES material(id),
    batch_no VARCHAR(100),                 -- 批次号
    quantity DECIMAL(18,2) NOT NULL,       -- 数量
    location_id BIGINT REFERENCES location(id),
    qc_status VARCHAR(20) DEFAULT 'PENDING' -- 质检状态
);
```

### 2.2 索引设计

```sql
-- 库存查询优化
```

## 3. API 设计

### 3.1 RESTful API 规范

**URL 命名规范**：
- 资源名称使用复数形式：`/materials`、`/warehouses`
- 使用连字符分隔：`/inbound-orders`
- 版本号放在 URL 中：`/api/v1/materials`

**HTTP 方法**：
| 方法 | 用途 | 示例 |
|------|------|------|
| GET | 查询 | GET /api/v1/materials |
| POST | 创建 | POST /api/v1/inbound-orders |
| PUT | 全量更新 | PUT /api/v1/materials/{id} |
| PATCH | 部分更新 | PATCH /api/v1/inventory/{id} |
| DELETE | 删除 | DELETE /api/v1/materials/{id} |

### 3.2 核心 API 列表

**库存管理 API**：
```
GET    /api/v1/inventory                    # 查询库存列表
GET    /api/v1/inventory/{id}               # 查询库存详情
GET    /api/v1/inventory/search             # 多条件查询
POST   /api/v1/inventory/reserve            # 预留库存
DELETE /api/v1/inventory/reserve/{id}       # 取消预留
```

**入库管理 API**：
```
POST   /api/v1/inbound-orders               # 创建入库单
GET    /api/v1/inbound-orders               # 查询入库单列表
GET    /api/v1/inbound-orders/{id}          # 查询入库单详情
PUT    /api/v1/inbound-orders/{id}          # 更新入库单
POST   /api/v1/inbound-orders/{id}/qc       # 提交质检结果
```

**出库管理 API**：
```
POST   /api/v1/outbound-orders              # 创建出库单
GET    /api/v1/outbound-orders              # 查询出库单列表
POST   /api/v1/outbound-orders/{id}/confirm # 确认出库
```

### 3.3 响应格式

**成功响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "code": "M001",
    "name": "螺丝 M8x20"
  }

```

**错误响应**：

## 4. 部署架构

### 4.1 容器化部署

```yaml
# docker-compose.yml 示例
version: '3.8'
services:
  gateway:
    image: iwms/gateway:latest
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
  
  inventory:
    image: iwms/inventory:latest
    ports:
      - "8082:8082"
    depends_on:
      - postgres
      - redis
  
  postgres:
    image: postgres:14
    environment:
      - POSTGRES_DB=iwms
      - POSTGRES_USER=iwms
      - POSTGRES_PASSWORD=secret
    volumes:
      - pgdata:/var/lib/postgresql/data
  
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:
```

### 4.2 Kubernetes 部署

```yaml
# deployment.yaml 示例
apiVersion: apps/v1
kind: Deployment

  name: inventory-service
spec:
  replicas: 3

            memory: "512Mi"

          limits:
            memory: "1Gi"

        livenessProbe:
          httpGet:
            path: /actuator/health
            port: 8082
          initialDelaySeconds: 30
          periodSeconds: 10
```

### 4.3 高可用设计

1. **服务层**：每个服务至少 3 个副本，K8s 自动故障转移
2. **数据库**：PostgreSQL 主从复制，读写分离
3. **缓存**：Redis Cluster，3 主 3 从
4. **消息队列**：RabbitMQ 镜像队列，保证消息不丢失
5. **负载均衡**：Nginx + K8s Service，轮询策略

## 5. 安全设计

### 5.1 认证授权

- **JWT Token**：用户登录后颁发 JWT，有效期 2 小时
- **Refresh Token**：用于刷新 JWT，有效期 7 天
- **权限控制**：基于 RBAC 模型，角色-权限-菜单三级控制

### 5.2 数据安全

- **传输加密**：HTTPS + TLS 1.3
- **存储加密**：敏感数据（密码、手机号）AES 加密存储
- **SQL 注入防护**：使用参数化查询，禁止拼接 SQL
- **XSS 防护**：前端输入过滤，后端输出编码

### 5.3 审计日志

- **操作日志**：记录所有增删改操作，包含操作人、时间、IP、操作内容
- **登录日志**：记录登录成功/失败，包含 IP、设备信息
- **日志保留**：操作日志保留 1 年，登录日志保留 6 个月
