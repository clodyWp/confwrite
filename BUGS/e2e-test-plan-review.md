# E2E 测试计划审查报告

**审查时间**: 2026-10-12  
**审查对象**: `scripts/E2E-TEST-PLAN.md` + `scripts/e2e-test-herdr.ps1`  
**审查结论**: ⚠️ **部分可执行，但有结构性问题需修复**

---

## 审查结论

- ✅ 整体流程和阶段覆盖合理
- ✅ 配套 PS1 脚本提供了真正的自动化价值
- ❌ 命令签名不一致会混淆执行者
- ❌ 跨平台支持不完整（仅 PS1）
- ❌ 缺少关键测试场景（中断恢复、429、compact、export）
- ❌ 无自动化产物验证
- ❌ 章节编号错误

---

## P1 问题（必须修复）

### P1-1: 命令签名不一致

**问题**: E2E 计划 §1.2 显示命令带 `<slug>` 参数，但 SKILL.md 定义不带。

| 来源 | organize | write |
|------|----------|-------|
| E2E 计划 | `/confwrite:organize <slug>` | `/confwrite:write <slug>` |
| SKILL.md | `/confwrite:organize` | `/confwrite:write` |

**修复**: 更新 §1.2，注明 `<slug>` 是可选参数，说明何时使用哪种形式。

---

### P1-2: §5 章节编号错误

**问题**: §5 "异常处理" 的子章节编号为 4.2-4.9，应该是 5.2-5.9。

```
### 4.2 P0：命令执行失败    ← 应该是 5.2
### 4.3 P1：远程 pi 自行分析代码  ← 应该是 5.3
...
```

---

### P1-3: 缺少 `/confwrite:compact` 和 `/confwrite:export` 命令

**问题**: 测试计划遗漏了两个已注册命令：
- `/confwrite:compact` — 防止长写作时 429 错误
- `/confwrite:export` — 显式导出控制

---

### P1-4: 跨平台不兼容

**问题**: 计划混合使用 bash 和 PowerShell，无明确平台指导：
- §2.3 使用 `ssh` + bash
- §4.3 使用 PowerShell
- 配套脚本仅 `.ps1`，无 `.sh` 版本

---

## P2 问题（建议修复）

### P2-1: 无自动化清理或测试数据隔离

测试不可重复执行，缺少 teardown 步骤。

### P2-2: 缺少关键测试场景

| 缺失场景 | 风险 |
|----------|------|
| 空输入（无 reference_material） | 可能导致 organize 崩溃 |
| 中断恢复（kill pi 后 resume） | 核心卖点未测试 |
| 429 限流恢复 | AGENTS.md 明确提到 |
| 导出格式验证 | 仅检查文件存在 |
| `/confwrite:compact` 测试 | 防止上下文溢出 |
| 并发项目操作 | 测试调度器 |

### P2-3: 验证标准缺乏自动化

§3.5 验证仅为手动检查清单，无自动化断言。

### P2-4: 计划与脚本的 cwd 处理矛盾

- 计划 §1.1: "不需要 cd 到项目目录"
- 脚本: 先 cd 到项目目录再执行命令

### P2-5: 配置文件 heredoc 语法脆弱

§3.1.1 使用 SSH 内 bash heredoc 创建配置文件，容易出错。

---

## 优化建议

1. **统一命令签名**: §1.2 与 SKILL.md 对齐
2. **修复章节编号**: §5 子章节从 4.x 改为 5.x
3. **添加 compact 和 export 到流程**: §3.4 和 §3.5
4. **创建 bash 配套脚本**: `e2e-test-herdr.sh`
5. **添加 teardown 步骤**: 清理命令和 `--cleanup` 标志
6. **添加产物验证到脚本**: 文件数量、字数、DOCX 有效性
7. **解决 cwd 矛盾**: 统一方案
8. **添加中断/恢复测试场景**: 核心差异化功能

---

## 最终评估

**可执行性**: ⚠️ 部分可执行

该计划可以指导有经验的执行者进行手动测试，但还不是严格的、可重复的、跨平台的 E2E 测试规范。P1 问题应在正式测试前修复。
