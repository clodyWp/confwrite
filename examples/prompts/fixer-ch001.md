## 实际 Prompt

```markdown
# 修复任务

你需要根据审阅反馈修复章节 **ch001** 的内容。

## 原始章节内容

# ch001 项目背景与目标

## 概述

本章节介绍项目的背景信息和核心目标。

## 项目背景

随着企业数字化转型的深入，对 Web 应用系统的需求日益增长。本项目旨在构建一个高性能、高可用的企业级 Web 应用系统。

### 业务背景

当前企业面临以下挑战：
- 用户规模快速增长
- 数据安全要求提高
- 系统可用性要求严格

### 技术背景

从技术角度，系统需要：
- 采用 RESTful API 设计
- 实现 OAuth2.0 认证
- 使用 PostgreSQL 和 Redis

## 项目目标

### 核心目标

1. **用户管理系统**
   - 支持用户注册和登录
   - 实现权限控制
   - 支持多租户架构

2. **数据管理系统**
   - 支持 CRUD 操作
   - 实现数据分页查询

### 性能目标

系统需要达到以下性能指标：
- 系统可用性: 99.9%
- 平均响应时间: < 200ms
- 最大并发用户数: 5000

## 小结

本章节介绍了项目的背景信息和核心目标。

## 审阅反馈

# ch001 审阅报告

## 结论
**决定**: revise

## 评分
- 内容准确性: 7/10
- 数据一致性: 4/10
- 结构清晰度: 8/10
- 文字质量: 7/10

## 问题列表
1. [严重程度: 高] 数据不一致：系统可用性写的是 99.9%，基线要求是 99.99%
   - 位置: "### 性能目标" 段落
   - 建议: 修改为 "系统可用性: 99.99%"

2. [严重程度: 高] 数据不一致：平均响应时间写的是 < 200ms，基线要求是 < 100ms
   - 位置: "### 性能目标" 段落
   - 建议: 修改为 "平均响应时间: < 100ms"

3. [严重程度: 高] 数据不一致：最大并发用户数写的是 5000，基线要求是 10000
   - 位置: "### 性能目标" 段落
   - 建议: 修改为 "最大并发用户数: 10000"

4. [严重程度: 中] 需求覆盖不完整：未提及"必须满足等保二级安全要求"
   - 位置: "## 项目目标" 部分
   - 建议: 在安全目标中补充等保要求

5. [严重程度: 低] 内容过于简略：业务背景部分缺少具体数据支撑
   - 位置: "### 业务背景" 段落
   - 建议: 补充具体的业务场景和数据

## 优点
- 章节结构清晰，层次分明
- 技术术语使用正确
- 概述简洁明了

## 总结
章节整体结构良好，但存在严重的数据一致性问题。性能指标与基线数据不符，需要修正后重新审阅。

## 修复要求

1. **解决所有问题**：逐一解决审阅报告中列出的所有问题
2. **保持结构**：除非审阅报告明确要求，不要大幅改变章节结构
3. **数据准确**：确保所有数据与基线一致
4. **改进质量**：根据审阅建议改进文字质量

## 输出格式

将修复后的章节内容写入文件：**drafts/chapters/ch001.md**

注意：完全覆盖原文件，不要保留原始内容。
```

## 关键点

1. **Prompt 结构**：
   - 任务说明
   - 原始章节内容（完整嵌入）
   - 审阅反馈（完整嵌入审阅报告）
   - 修复要求
   - 输出格式

2. **Fixer 的职责**：
   - 阅读审阅报告中的问题列表
   - 逐一修复每个问题
   - 保持原有结构（除非审阅报告要求改变）
   - 确保数据与基线一致
   - 将修复后的内容写入 `drafts/chapters/ch001.md`（覆盖原文件）

3. **修复后的流程**：
   - Fixer 完成后，章节状态变为 `written`
   - 状态机进入审阅阶段（Phase 4b）
   - Reviewer 再次审阅修复后的内容
   - 如果通过，状态变为 `completed`
