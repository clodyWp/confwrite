# 示例 Prompt：Reviewer Subagent

本文件展示 Reviewer subagent 接收到的完整 prompt 示例。

---

## 实际 Prompt

```markdown
# 审阅任务

你需要审阅章节 **ch001** 的内容。

## 章节内容

# ch001 项目背景与目标

## 概述

本章节介绍项目的背景信息和核心目标。

## 项目背景

随着企业数字化转型的深入，对 Web 应用系统的需求日益增长。本项目旨在构建一个高性能、高可用的企业级 Web 应用系统。

### 业务背景

当前企业面临以下挑战：
- 用户规模快速增长
- 数据安全要求提高
- 系统可用性要求严格

### 技术背景

从技术角度，系统需要：
- 采用 RESTful API 设计
- 实现 OAuth2.0 认证
- 使用 PostgreSQL 和 Redis

## 项目目标

### 核心目标

1. **用户管理系统**
   - 支持用户注册和登录
   - 实现权限控制
   - 支持多租户架构

2. **数据管理系统**
   - 支持 CRUD 操作
   - 实现数据分页查询

### 性能目标

系统需要达到以下性能指标：
- 系统可用性: 99.9%
- 平均响应时间: < 200ms
- 最大并发用户数: 5000

## 小结

本章节介绍了项目的背景信息和核心目标。

## 数据基线

以下是跨章节共享的数据，必须确保章节内容与基线一致：

### 关键指标
- 系统可用性: 99.99%
- 平均响应时间: < 100ms
- 最大并发用户数: 10000

### 技术术语
RESTful, OAuth2.0, PostgreSQL, Redis, JWT, HTTPS, CRUD

### 需求要点
- 必须支持用户注册和登录
- 需要实现细粒度的权限控制
- 必须支持多租户架构
- 系统可用性: 99.99%
- 平均响应时间: < 100ms
- 最大并发用户数: 10000

## 审阅标准

1. **数据一致性**：检查所有数字、指标是否与基线一致
2. **术语准确性**：检查技术术语使用是否正确
3. **需求覆盖**：检查是否覆盖了所有需求要点
4. **内容准确性**：检查技术内容是否准确
5. **结构清晰度**：检查章节结构是否合理
6. **文字质量**：检查语法、拼写、表达是否清晰

## 输出格式

将审阅报告写入文件：**review/ch001-review.md**

文件格式：
```markdown
# ch001 审阅报告

## 结论
**决定**: accept | reject | revise

## 评分
- 内容准确性: X/10
- 数据一致性: X/10
- 结构清晰度: X/10
- 文字质量: X/10

## 问题列表
1. [严重程度: 高/中/低] 问题描述
   - 位置: 具体段落或句子
   - 建议: 修改建议

## 优点
- 列出章节的优点

## 总结
总体评价和改进建议
```

## 决定标准

- **accept**: 质量达标，可以直接使用
- **revise**: 有小问题，需要修改后重新审阅
- **reject**: 质量问题严重，需要重写
```

---

## 关键点

1. **Prompt 结构**：
   - 任务说明
   - 章节内容（完整嵌入草稿）
   - 数据基线（完整嵌入）
   - 审阅标准
   - 输出格式
   - 决定标准

2. **Reviewer 的职责**：
   - 对比章节内容与数据基线
   - 检查数据一致性（最重要）
   - 检查术语准确性
   - 检查需求覆盖
   - 给出 accept/revise/reject 决定
   - 将审阅报告写入 `review/ch001-review.md`

3. **决定标准**：
   - **accept**: 数据一致，内容准确，结构清晰
   - **revise**: 有小问题（如数据不一致），修改后可接受
   - **reject**: 质量问题严重（如大量数据错误、内容偏离主题），需要重写
