# Spec: 基线提取器表格处理

**Issue**: #125  
**状态**: Draft  
**创建时间**: 2026-10-15

## 背景

基线提取器在处理包含表格的 Markdown 文档时，会将表格单元格内的冒号误解析为分隔符，导致基线项被错误分割。

**示例**：
```markdown
| 时间范围 | 状态 |
|----------|------|
| 31-60天: 完成 | ✅ |
```

当前行为：提取 key=`31-60天`，value=`完成`  
期望行为：提取 key=`31-60天: 完成`（完整单元格内容）

## 不变量

### BE-1: 表格行内的冒号不作为分隔符

**前置条件**：当前行是 Markdown 表格行（以 `|` 开头和结尾）  
**后置条件**：`extractContext` 返回完整单元格内容（截断到 15 字符），不在冒号处分割

**验证方法**：单元测试

### BE-2: 普通文本的冒号仍作为分隔符

**前置条件**：当前行不是表格行  
**后置条件**：`extractContext` 返回冒号前的部分（截断到 15 字符）

**验证方法**：单元测试

### BE-3: 表格单元格内容完整提取

**前置条件**：正则匹配到数字/百分比/时间等内容  
**后置条件**：如果匹配在表格单元格内，key 使用完整单元格内容

**验证方法**：单元测试

### BE-4: 基线匹配使用完整项

**前置条件**：基线已提取完成  
**后置条件**：`finalizer.checkConsistency` 能够匹配到表格中的完整基线项

**验证方法**：集成测试

### BE-5: 分隔行不被当作表格行处理

**前置条件**：当前行是 Markdown 表格分隔行（如 `|---|---|`）  
**后置条件**：`isTableRow` 返回 false，不进入表格处理逻辑

**验证方法**：单元测试

### BE-6: 15 字符截断规则一致

**前置条件**：提取的 key 超过 15 字符  
**后置条件**：无论普通文本还是表格单元格，都截断到 15 字符

**验证方法**：单元测试

## 边界情况

1. **全角冒号**：`| 时间：31-60天 |` — 应完整提取
2. **多冒号单元格**：`| 时间: 31-60天: 完成 |` — 应完整提取（不分割）
3. **空表格**：只有 header 和 separator，无数据行 — 不产生基线项
4. **混合内容**：同一文档包含表格和普通文本 — 各自正确处理
5. **重复单元格内容**：`| 达标 | 达标 |` — 正确定位到匹配偏移的单元格

## 实现约束

- 向后兼容：非表格内容的提取逻辑不变
- 性能影响：表格检测只在提取时执行一次
- 不使用外部 Markdown 解析库
