## 选型决策流程

```
需要画什么？
├── 展示系统结构 → 架构图
├── 展示执行步骤 → 流程图
├── 展示调用顺序 → 时序图
├── 展示数据结构 → ER 图
├── 展示状态变化 → 状态机图
├── 展示代码结构 → 类图
├── 展示部署环境 → 部署图
├── 展示数据流转 → 数据流图
└── 展示方案对比 → 对比表
```

## 文档场景 → 图表组合

| 文档场景 | 推荐图表组合 |
|---------|------------|
| 架构设计文档 | 架构图 + ER图 + 部署图 + 类图 |
| API 接口文档 | 时序图 + 数据流图 + 状态机图 |
| 需求/PRD | 流程图 + 状态机图 |
| 技术选型 | 对比表 + 架构图 |
| 运维手册 | 部署图 + 流程图（告警处理） |
| 故障复盘 | 时序图 + 架构图 + 数据流图 |
| 新人入职 | 架构图 + ER图 + 流程图 + 部署图 |
| 测试文档 | 流程图 + 状态机图 + 时序图 |

## 工具选择

| 场景 | 推荐工具 | 原因 |
|------|---------|------|
| Markdown 内嵌 | Mermaid | 纯文本，git 友好 |
| 完整 UML | PlantUML | 支持所有 UML 图类型 |
| 正式汇报 | draw.io | 专业美观 |
| 快速讨论 | Excalidraw | 手绘风格 |
| 数据库设计 | dbdiagram.io | 专为 ER 图设计 |
| 架构即代码 | Structurizr | C4 模型支持 |

---

## 绘图核心原则

1. **读者决定图表** — 先想清楚谁看，再决定画什么
2. **一图一目的** — 每张图只回答一个问题
3. **文字辅助** — 关键决策用文字说明
4. **保持更新** — 过时的图比没有图更危险
5. **工具统一** — 团队统一工具，方便维护
