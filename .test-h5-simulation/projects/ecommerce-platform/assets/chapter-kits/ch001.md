## 绘图核心原则

1. **读者决定图表** — 先想清楚谁看，再决定画什么
2. **一图一目的** — 每张图只回答一个问题
3. **文字辅助** — 关键决策用文字说明
4. **保持更新** — 过时的图比没有图更危险
5. **工具统一** — 团队统一工具，方便维护

## 布局原则（必须遵循）

## 七条布局原则（按优先级排序）

### 原则 1：分组压缩（Chunking）

当信息块 > 5 时，必须分组：
- 用**容器**（浅色背景块、虚线框、圆角大框）包裹相关模块
- 容器必须有标签（如"数据层"、"业务服务"、"接入网关"）
- 容器之间间距 > 容器内部模块间距（至少 **2:1** 比例）
- 容器数量控制在 **3-4 个**
- 大脑看到的是容器，不是散落的模块

### 原则 2：视觉权重分层（Visual Hierarchy）

不是所有模块同等重要：

| 权重 | 手段 | 用途 |
|------|------|------|
| 高 | 深色填充、大尺寸（+20%）、粗边框 | 核心模块（≤3个） |
| 中 | 浅色填充、标准尺寸 | 常规模块 |
| 低 | 灰色/白色填充、小尺寸、细边框 | 辅助模块 |

关键：高权重元素**不超过 2-3 个**。全部突出 = 没有突出。

### 原则 3：视觉路径引导（Visual Flow）

告诉观众先看哪后看哪：
- **位置优先级**：左上角是视觉起点（阅读习惯），最重要的放左上
- **大小梯度**：大模块 → 中模块 → 小模块，形成自然视线流动
- **颜色引导**：用一条"色彩路径"串联关键模块（如核心流程用橙色，其余灰色）
- **编号**：顺序重要时直接加编号（①②③），最直白但最有效

### 原则 4：重复模式（Visual Rhythm）

同类元素必须一致，降低逐个解读成本：
- 所有同类模块**同形状、同尺寸**（除非权重不同）
- 同类模块**同颜色**
- 文字位置统一（都居中，或都左对齐）
- 连线样式统一（同粗细、同颜色、同箭头）

### 原则 5：连线简化（Connection Management）

连线数量不超过模块数的 **1.5 倍**。超过时选择简化策略：

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| 省略显而易见的 | 相邻层默认互通，不画线 | 分层架构 |
| 总线化 | 一条粗线代表通道，分支连到各模块 | 数据流、消息总线 |
| 颜色编码 | 不同类型的关系用不同颜色 | 多种调用关系并存 |
| 只画关键路径 | 只展示核心流程连线，辅助关系不画 | 汇报场景 |
| 分组间连线 | 不在模块间连线，在容器间连线 | 高层架构图 |

### 原则 6：标注外置（Label Externalization）

模块内部只放**最核心的 1-3 个词**，详细说明外置：
- 模块内：`用户服务`
- 图例区（编号对应）：① 用户服务：负责注册、登录、权限管理、SSO 集成
- 好处：模块保持简洁，不因文字过多撑大尺寸破坏对齐

### 原则 7：边界清晰（Enclosure & Proximity）

格式塔核心原则——物理距离决定感知分组：
- 组内间距：小（如 10px）
- 组间间距：大（如 40-60px）
- 间距比至少 **3:1**，否则观众分不清谁和谁是一组
- 用背景色块/虚线框强化分组边界

## 图表格式

使用 diagram-start 标记，内部是 containers / nodes / edges 三段：

```
<!-- diagram-start
type: flow
title: 图表标题
description: |
  一段话说明这张图表达什么（不画进图里）
containers:
  - id: c1
    label: 分组名
    nodes: [a, b]
nodes:
  - id: a
    label: 节点文字（≤12 字）
    container: c1
    high_weight: true   # 全图最多 3 个
edges:
  - from: a
    to: b
    label: 短标签
diagram-end -->
```

硬性要求：**一张图装下全部内容**（引擎会压缩到 ≤1 页，
节点 ≤24、连线 ≤28），不要拆成多张；**严禁 mermaid 代码块**。
