## 视觉表现形式

- **核心元素**：圆角矩形/椭圆（状态）+ 箭头（状态转换）+ 箭头标注（触发条件/事件）
- **初始状态**：实心圆点
- **终止状态**：带环的实心圆点
- **复合状态**：状态内嵌套子状态图
- **可标注**：guard condition（守卫条件）、action（动作）、event（事件）

## 使用场景

| 场景 | 目的 |
|------|------|
| 业务对象状态管理 | 订单、支付、审批等有复杂状态流转的场景 |
| 需求文档 | 明确业务对象的所有状态和转换条件 |
| 测试文档 | 梳理状态转换的测试用例和边界条件 |
| 开发实现 | 指导状态机代码的编写 |

## 适用文档类型

PRD/需求文档、测试计划、技术方案、业务规则文档

| 工具 | 适用情况 |

## 绘图要点

1. 列出所有可能的状态，不要遗漏
2. 每个转换箭头标注触发事件和条件
3. 标注不可能发生的转换（显式说明"不能从X直接到Y"）
4. 复合状态用于简化复杂流程（如"订单处理"包含多个子状态）
5. 终态要明确，每个流程都要有出口
