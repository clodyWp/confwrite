## 视觉表现形式

- **表格 + 评分标记**：星级⭐、勾选✅、叉号❌
- **结构**：维度行 × 方案列
- **可包含**：权重、评分、推荐理由
- **决策树**：菱形节点 + 条件分支（用于展示选型判断逻辑）

## 典型结构

| 维度 | 方案A | 方案B | 方案C |
|------|:-----:|:-----:|:-----:|
| 性能 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| 易用性 | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 社区活跃度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| 学习成本 | 中 | 低 | 高 |
| 推荐度 | ✅ 推荐 | 备选 | ❌ |

## 使用场景

| 场景 | 目的 |
|------|------|
| 技术选型 | 横向比较多个方案的优劣 |
| RFC/ADR | 记录为什么选择某个方案 |
| 方案评审 | 提供量化的对比依据 |
| 汇报材料 | 向管理层展示选型结论 |

## 适用文档类型

RFC、ADR（架构决策记录）、技术选型报告、汇报材料

## 推荐工具

| 工具 | 适用情况 |
|------|---------|
| Markdown 原生表格 | 文档内嵌，git 友好 |
| draw.io | 需要视觉美化 |
| Excel / Google Sheets | 需要复杂计算和权重 |

## 绘图要点

1. 维度选择要全面（性能、成本、易用性、社区、学习曲线）
2. 评分标准统一（同一维度用同一标准打分）
3. 给出明确的推荐结论，不要模棱两可
4. 关键差异点用文字补充说明
5. 决策树用于展示"什么条件下选什么"的逻辑
