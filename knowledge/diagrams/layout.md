# 技术图形布局设计方法论

## 本质原理

### 一、认知负荷：审美的底层是脑科学

所有"好看"的规则，底层都在回答同一个问题：**如何让大脑用最少力气理解最多信息？**

人脑工作记忆同时只能处理 **4±1 个信息块**（Cowan 2001 修正了 Miller 的 7±2）。这意味着：

- 一张图如果同时有 8 个独立模块要理解，大脑已经过载了
- **对齐**的本质不是"整齐"，而是让大脑不用花算力去"推断位置关系"——对齐用空间结构直接映射了逻辑结构
- **等间距**的本质是消除歧义——间距不等时，大脑会反复犹豫"这两个是不是更近/更远"，每一次犹豫都是认知浪费
- **配色克制**的本质是编码通道不超载——人能同时区分的颜色类别上限就是 5-7 种，超过就开始混淆

> **"好看" = 认知摩擦最小化。** 不是主观偏好，是客观的效率指标。

### 二、信噪比：审美的信息论解释

香农的信噪比概念可以直接迁移到视觉设计：

- **信号** = 携带信息的视觉元素（模块的位置、颜色差异、连线方向）
- **噪声** = 不携带信息的视觉元素（阴影、渐变、3D、装饰花纹、多余边框）

关键洞察：**噪声不是中性的，它会干扰信号。** 每加一个装饰元素，不只是"多了一个东西"，而是让其他所有元素的辨识度都下降了一点。这是指数级的干扰，不是线性的。

> **信号密度 = 信息量 / 视觉元素数，分母越大，密度越低。** "少即是多"是信息论的必然结论。

### 三、视觉诚实：图形的"道德"问题

架构图是现实系统的**映射**，映射有真假之分：

- 如果系统本身是清晰的、分层的，但图画得混乱不堪——这是**低估**了系统，视觉复杂度 > 信息复杂度，属于"不诚实"
- 如果系统本身很复杂，但图画得像只有三个模块——这是**隐瞒**了复杂度，同样是"不诚实"
- 好的架构图让**视觉复杂度精确匹配信息复杂度**——不多一笔，不少一笔

> **最高级的视觉设计，是让人忘记视觉的存在。** 观众记住的是"系统怎么运作"，不是"图画得好看"。

### 四、格式塔与流畅感

为什么人脑对"对齐"有正向反馈？

- 大脑天生倾向于在混乱中寻找**模式**（pattern recognition）
- 当视觉元素严格对齐时，大脑的模式识别系统瞬间完成分组，产生"流畅感"（processing fluency）
- 流畅感本身会触发微弱的正向情绪——**人会觉得"好看"，本质上是"处理起来很顺畅"的副产物**

反过来，当一个元素偏离了对齐网格，大脑的模式识别会"卡壳"——产生微弱的不适感。

## 七条布局原则（按优先级排序）

### 原则 1：分组压缩（Chunking）

当信息块 > 5 时，必须分组：
- 用**容器**（浅色背景块、虚线框、圆角大框）包裹相关模块
- 容器必须有标签（如"数据层"、"业务服务"、"接入网关"）
- 容器之间间距 > 容器内部模块间距（至少 **2:1** 比例）
- 容器数量控制在 **3-4 个**
- 大脑看到的是容器，不是散落的模块

### 原则 2：视觉权重分层（Visual Hierarchy）

不是所有模块同等重要：

| 权重 | 手段 | 用途 |
|------|------|------|
| 高 | 深色填充、大尺寸（+20%）、粗边框 | 核心模块（≤3个） |
| 中 | 浅色填充、标准尺寸 | 常规模块 |
| 低 | 灰色/白色填充、小尺寸、细边框 | 辅助模块 |

关键：高权重元素**不超过 2-3 个**。全部突出 = 没有突出。

### 原则 3：视觉路径引导（Visual Flow）

告诉观众先看哪后看哪：
- **位置优先级**：左上角是视觉起点（阅读习惯），最重要的放左上
- **大小梯度**：大模块 → 中模块 → 小模块，形成自然视线流动
- **颜色引导**：用一条"色彩路径"串联关键模块（如核心流程用橙色，其余灰色）
- **编号**：顺序重要时直接加编号（①②③），最直白但最有效

### 原则 4：重复模式（Visual Rhythm）

同类元素必须一致，降低逐个解读成本：
- 所有同类模块**同形状、同尺寸**（除非权重不同）
- 同类模块**同颜色**
- 文字位置统一（都居中，或都左对齐）
- 连线样式统一（同粗细、同颜色、同箭头）

### 原则 5：连线简化（Connection Management）

连线数量不超过模块数的 **1.5 倍**。超过时选择简化策略：

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| 省略显而易见的 | 相邻层默认互通，不画线 | 分层架构 |
| 总线化 | 一条粗线代表通道，分支连到各模块 | 数据流、消息总线 |
| 颜色编码 | 不同类型的关系用不同颜色 | 多种调用关系并存 |
| 只画关键路径 | 只展示核心流程连线，辅助关系不画 | 汇报场景 |
| 分组间连线 | 不在模块间连线，在容器间连线 | 高层架构图 |

### 原则 6：标注外置（Label Externalization）

模块内部只放**最核心的 1-3 个词**，详细说明外置：
- 模块内：`用户服务`
- 图例区（编号对应）：① 用户服务：负责注册、登录、权限管理、SSO 集成
- 好处：模块保持简洁，不因文字过多撑大尺寸破坏对齐

### 原则 7：边界清晰（Enclosure & Proximity）

格式塔核心原则——物理距离决定感知分组：
- 组内间距：小（如 10px）
- 组间间距：大（如 40-60px）
- 间距比至少 **3:1**，否则观众分不清谁和谁是一组
- 用背景色块/虚线框强化分组边界

## 布局规划流程（v2 设计）

### 职责分离

| 步骤 | 职责 | 输入 | 输出 |
|------|------|------|------|
| 解析 | 理解内容 | 用户描述 | 元素清单 + 结构分析 |
| **布局规划** | **决定怎么排** | 结构分析 + 风格偏好 | **布局方案** |
| 生成 | 写代码 | 布局方案 + 风格偏好 | SVG 文件 |

### 结构分析（解析阶段增强）

对提取的元素进行深度分析，输出结构报告：

```
结构分析报告：
  - 信息块总数：N 个
  - 自然分组：[组名: [模块列表], ...]
  - 核心模块：[模块名]（用户强调的 / 处于中心位置的）
  - 辅助模块：[模块名]（支撑性的 / 可降权的）
  - 主路径/主流向：[起点] → [中间] → [终点]
  - 连线复杂度：简单(≤5) / 中等(6-12) / 复杂(>12)
  - 文字密度评估：低(≤3字/模块) / 中(4-8字) / 高(>8字)
```

**分析规则：**
- 信息块 ≤ 5 → 可直接平铺，无需分组压缩
- 信息块 6-7 → 建议分组，但不强制
- 信息块 ≥ 8 → **必须分组**，进入分组压缩策略
- 连线数 / 模块数 > 1.5 → 标记为"连线复杂"，需要简化策略
- 文字 > 8 字/模块 → 标记为"高文字密度"，需要标注外置策略

### 布局方案输出格式

```
布局方案：
  画布尺寸：WxH
  布局方向：从上到下 / 从左到右 / 从外到内
  分组方案：
    - 容器A "名称": [模块1, 模块2, 模块3]
    - 容器B "名称": [模块4, 模块5]
    - ...
  视觉权重：
    - 高：[模块名]（深色、大尺寸）
    - 中：[模块名]（标准）
    - 低：[模块名]（灰色、小尺寸）
  阅读路径：起点 → 方向 → 终点
  连线策略：[省略/总线化/颜色编码/关键路径/分组间连线]
  标注方式：[内嵌/外置]
  间距参数：
    - 组内间距：Xpx
    - 组间间距：Xpx
    - 边缘留白：Xpx
```

**用户确认点：** 布局方案输出后，等待用户确认或调整，再进入生成阶段。

## 检查清单

### 布局规划阶段（P4 Review 使用）

做完布局规划后问自己：

- [ ] 信息块 > 5 时，是否分组了？容器数量 ≤ 4？
- [ ] 高权重模块 ≤ 3 个？
- [ ] 阅读路径是否清晰（从哪开始，往哪走）？
- [ ] 同类模块是否一致（形状、尺寸、颜色）？
- [ ] 连线数 / 模块数 ≤ 1.5？超过时是否简化了？
- [ ] 文字 > 8 字/模块时，是否外置标注了？
- [ ] 组间/组内间距比 ≥ 3:1？
- [ ] 布局方案是否经过用户确认？

### 渲染后验证阶段（P5 使用）

SVG/PNG 生成后，执行以下自动化检查：

#### 1. 节点重叠检测

**规则**：任意两个节点的 bounding box 不应重叠（间距 > 0）。

**检测方法**：
```
对每对节点 (A, B):
  如果 A.right > B.left 且 A.left < B.right 且 A.bottom > B.top 且 A.top < B.bottom:
    → 标记为"节点重叠"
```

**阈值**：节点间距 ≥ 10px（防止视觉粘连）。

#### 2. 文字溢出检测

**规则**：节点内文字不应超出节点边界。

**检测方法**：
```
对每个节点:
  估算文字宽度 = 字符数 × 平均字符宽度（中文字符 × 12px，英文 × 7px）
  如果 文字宽度 > 节点宽度 - 20px（左右 padding）:
    → 标记为"文字可能溢出"
```

**补救**：触发文字换行算法，或缩小字体，或增大节点。

#### 3. 连线交叉检测

**规则**：连线之间不应交叉（除非 unavoidable）。

**检测方法**：
```
对每对连线 (L1, L2):
  计算两条线段是否相交
  如果相交:
    → 标记为"连线交叉"
```

**阈值**：交叉数 ≤ 2（少量交叉可接受，过多则布局失败）。

**补救**：调整节点位置，或使用曲线连线。

#### 4. 层级数量检测

**规则**：层级数不应过多，避免图太长。

**检测方法**：
```
统计 layerIndex 的最大值
如果 层级数 > 6:
  → 标记为"层级过多"
```

**阈值**：
- 架构图：≤ 5 层
- 流程图：≤ 8 层
- 超过阈值时，**优先按下面的压缩顺序压到阈值内**（压边距 → 压层间距 → 压字号），不要拆成多张图

#### 5. 节点标签截断检测

**规则**：节点标签不应被截断。

**检测方法**：
```
对每个节点:
  如果 节点宽度 < 80px 且 标签字符数 > 6:
    → 标记为"标签可能被截断"
```

**补救**：增大节点宽度，或缩短标签文字。

#### 6. Word 尺寸兼容性检测

**规则**：图表尺寸应适合 Word 文档嵌入。

**检测方法**：
```
如果 SVG 宽度 > 680px:
  → 标记为"宽度过大，Word 嵌入可能溢出"
如果 SVG 高度 > 900px:
  → 标记为"高度过大，Word 分页可能切断"
```

**阈值**：
- 宽度：≤ 680px（Word A4 页面可用宽度）
- 高度：≤ 900px（Word A4 页面可用高度，留边距）
- 超过阈值时，缩放或拆分图表

#### 7. 装饰字符残留检测

**规则**：SVG 中不应包含 ASCII art 装饰字符。

**检测方法**：
```
扫描 SVG 文本内容
如果包含 [┌┐└┘├┤┬┴┼╔╗╚╝╠╣╦╩╬═║─│→▼▲◀▶←↓↑↕↔·]:
  → 标记为"装饰字符残留"
```

**补救**：在解析阶段过滤装饰字符。

#### 8. 图片文件完整性检测

**规则**：生成的 PNG 文件应完整可用。

**检测方法**：
```
对每个 PNG 文件:
  如果 文件大小 == 0:
    → 标记为"文件为空"
  如果 文件无法被图片库打开:
    → 标记为"文件损坏"
```

### 检查报告格式

P5 验证完成后，生成检查报告：

```json
{
  "diagramId": "ch04-v1-fig6",
  "checks": [
    { "name": "节点重叠", "passed": true, "details": "0 个重叠" },
    { "name": "文字溢出", "passed": true, "details": "0 个溢出" },
    { "name": "连线交叉", "passed": false, "details": "3 处交叉，建议调整布局" },
    { "name": "层级数量", "passed": true, "details": "4 层" },
    { "name": "标签截断", "passed": true, "details": "0 个截断" },

    { "name": "装饰字符", "passed": true, "details": "无残留" },

  ],

  "warnings": ["连线交叉 3 处"]

```

**阻塞规则**：
- 如果 `overallPassed == false` 且有 `passed: false` 的检查项 → 禁止进入 Phase 6
- 必须修复后重新生成

## 实践教训

### 项目目录规范

**问题：** 早期版本将 SVG 直接输出到 `workspace/diagrams/`，违反 AGENTS.md 的项目目录规范。

**修正：** 每张图必须使用项目目录：
```
projects/<project-slug>/
  README.md
  figures/
    └── {topic}-{YYYYMMDD}.svg
```

**规则：** 接到任务先建目录，SVG 输出到 `projects/<slug>/figures/`。
