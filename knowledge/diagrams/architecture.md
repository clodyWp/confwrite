## 视觉表现形式

- **核心元素**：方块（模块/服务）+ 箭头（调用方向）+ 分层布局
- **布局方式**：从上到下分层（表现层→服务层→数据层），或从左到右
- **颜色编码**：不同颜色区分不同职责域（蓝色=前端、绿色=后端、橙色=数据层）
- **常见变体**：4+1视图、C4模型（Context→Container→Component→Code）
- **方块内标注**：服务名称、技术栈、版本号

## 使用场景

| 场景 | 目的 |
|------|------|
| 新项目立项 | 让团队理解系统全貌 |
| 架构评审 | 评估系统设计的合理性 |
| 系统重构 | 对比重构前后的架构变化 |
| 新人入职 | 快速了解系统结构 |
| 技术方案 | 展示方案落地后的系统结构 |

## 适用文档类型

架构设计文档、技术方案文档、RFC、新人入职文档、故障复盘报告（标注影响范围）

## 推荐工具

| 工具 | 适用情况 |
|------|---------|
| Mermaid `graph TD/LR` | Markdown 内嵌，git 友好 |
| PlantUML | 需要完整 UML 支持 |
| draw.io | 正式文档/汇报 |
| Excalidraw | 快速原型/非正式讨论 |
| Structurizr | C4 模型，架构即代码 |

## 绘图要点

1. 分层清晰，上层调用下层，不要反向箭头
2. 每张图不超过 15 个节点，复杂系统拆成多张（C4 分层）
3. 箭头上标注协议（HTTP/gRPC/MQ）
4. 用颜色区分职责域，不要随意上色
5. 图后紧跟文字说明关键决策
