## 视觉表现形式

- **核心元素**：参与者方块（顶部）+ 纵向虚线（生命线）+ 横向箭头（消息）
- **箭头含义**：
  - 实线箭头 = 同步调用/请求
  - 虚线箭头 = 返回/响应
- **矩形块（激活条）** = 处理时间段
- **可包含**：循环框（loop）、条件框（alt/opt）、并行框（par）

## 典型结构

```
  用户        前端         后端         数据库
   │           │            │            │
   │──点击登录──▶│            │            │
   │           │──POST /login▶│           │
   │           │            │──查询用户───▶│
   │           │            │◀──返回数据───│
   │           │            │──生成Token──▶│
   │           │◀──200 OK───│            │
   │◀──跳转首页─│            │            │
```

## 使用场景

| 场景 | 目的 |
|------|------|
| API 文档 | 展示接口调用的先后顺序和交互协议 |
| 微服务架构 | 展示服务间的调用链 |
| 故障复盘 | 还原故障发生的调用时序 |
| 第三方对接 | 说明集成调用的完整流程 |

## 适用文档类型

API 文档、微服务调用链文档、故障复盘报告、SDK 接入指南

## 推荐工具

| 工具 | 适用情况 |
|------|---------|
| Mermaid `sequenceDiagram` | Markdown 内嵌，git 友好 |
| PlantUML | 功能最全，支持复杂交互 |
| draw.io | 需要高度自定义样式 |

## 绘图要点

1. 参与者按调用顺序从左到右排列
2. 每个参与者用有意义的名称（服务名/角色名）
3. 箭头上标注协议和接口路径（如 `POST /api/login`）
4. 用 alt/loop 框标注条件和循环，不要省略
5. 返回消息标注状态码或关键数据
