# E2E 测试问题分析 - v0.28.0 第三次迭代

## 问题分类

### 代码问题（需要修复）

#### 1. ch007 字数验证失败 (P1)

**症状**：
- ch007（附录章）在 5 轮审阅后仍无法通过字数验证
- 最终状态: `exceeded_max_rounds_validation`

**复现步骤**：
1. 创建包含附录章的项目
2. 运行 `/confwrite:write <slug>`
3. 观察 ch007 的审阅过程

**预期行为**：附录章应该能在合理轮次内通过字数验证

**实际行为**：5 轮后达到上限，标记为 failed

**根因假设**：
- 附录章包含大量表格、列表，字数难以精确控制
- 字数预算分配策略不适合附录章
- 字数验证逻辑过于严格

**影响**：
- ch007 被标记为 failed
- 但仍被组装进最终文档（行为不一致）

**建议修复方向**：
1. 为附录章设置更宽松的字数预算
2. 改进字数验证逻辑，考虑表格/列表的特殊性
3. 或者：failed 的章节不应该被组装进最终文档

#### 2. Verdict 矛盾检测 (P1)

**症状**：
```
Warning: ⚠️ 验证失败 (reviewer ch007):
  ❌ verdict 矛盾: verdict 为 accept，但审阅报告中发现字数问题
```

**复现步骤**：
1. Reviewer subagent 审阅章节
2. 返回 verdict: "accept"
3. 但审阅报告内容中提到字数问题

**预期行为**：
- 如果报告中有问题，verdict 应该是 "revise" 或 "reject"
- verdict 和报告内容应该一致

**实际行为**：
- verdict 是 "accept"
- 报告内容提到问题
- 独立验证器检测到矛盾

**根因假设**：
- Reviewer subagent 的 prompt 没有强制要求 verdict 和报告一致
- LLM 返回的 verdict 和报告内容不匹配

**影响**：
- 触发额外修复轮次
- 增加执行时间
- 可能导致循环

**建议修复方向**：
1. 改进 Reviewer 的 prompt，强制要求 verdict 和报告一致
2. 在 Reviewer 输出解析时进行一致性检查
3. 如果不一致，自动修正 verdict

---

#### 3. 基线提取解析问题 (P2)

**症状**：
- 130+ 项基线缺失
- 主要是带冒号的时间/数量片段

**复现步骤**：
1. 准备包含表格的素材文档
2. 运行 `/confwrite:organize <slug>`
3. 检查生成的 baseline

**预期行为**：
- 表格中的 `31-60天: 完成` 应该被提取为完整项

**实际行为**：
- 被解析为 `["31-60天", "完成"]` 两个独立项
- 导致匹配时出现截断不匹配

**根因假设**：
- 基线提取器将冒号视为分隔符
- 没有考虑表格中冒号的特殊含义

**影响**：
- 基线一致性检查显示 warning
- 不影响文档质量，但影响检查准确性

**建议修复方向**：
1. 改进基线提取逻辑，识别表格上下文
2. 或者：在匹配时使用模糊匹配（包含关系而非精确匹配）
