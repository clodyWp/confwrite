## 6. 发现的问题

### 6.1 ch007 字数验证超限

**症状**：
- ch007（附录章）在 5 轮审阅后仍无法通过字数验证
- 最终状态: `exceeded_max_rounds_validation`

**根因**：
- 附录章的特殊性质（包含大量表格、列表）导致字数难以精确控制
- 审阅器对字数验证过于严格

**影响**：
- ch007 被标记为 failed，但仍被组装进最终文档
- 不影响整体流程完成

### 6.2 Verdict 矛盾

**症状**：
```
Warning: ⚠️ 验证失败 (reviewer ch007):
  ❌ verdict 矛盾: verdict 为 accept，但审阅报告中发现字数问题
```

**根因**：
- Reviewer subagent 返回的 verdict 是 `accept`
- 但审阅报告内容中提到了字数问题
- 独立验证器检测到矛盾

**影响**：
- 触发了额外的修复轮次
- 增加了执行时间

### 6.3 基线提取解析问题

**症状**：
- 130+ 项基线缺失
- 主要是带冒号的时间/数量片段

**根因**：
- 基线提取器将表格中的冒号分隔符误解析为指标片段
- 例如：`31-60天: 完成` 被解析为 `31-60天` 和 `完成` 两个独立项

**影响**：
- 基线一致性检查显示 warning
- 不影响文档质量

### 6.4 执行时间过长

**症状**：
- 总耗时约 8 小时
- 多次超时（30 分钟限制）

**根因**：
- 远端 pi 使用 qwen3.7-plus 模型，响应较慢
- write-review-fix 循环需要多次迭代
- 循环检测导致任务终止和重试

**影响**：
- 用户体验不佳
- 资源消耗较大
